## 产品约定

- UniDocs 面向人和外部 AI Agent，共享 API，不内置聊天或 Agent runner。
- 作品身份稳定，只有 fork 创建另一件作品。“我的作品”是导航，不是文件夹或作品集，不做手工树形层级。
- 默认预览；Markdown 编辑采用源码/预览双栏；保留统一“新建作品”入口。
- 显式保存、乐观锁；冲突保留草稿，不自动覆盖或合并。
- 批注锚定明确版本，私有草稿集中发布一轮反馈；引用固定版本并显式升级。这些尚未接入生产。
- 定位链接不授予访问权，MVP 不做外部分享。
- 电脑和平板优先，手机暂显示“请在电脑或平板上查看”。延续现有原型和生产 UI，不重新设计视觉风格。

## 下一步：第 08 轮

目标是 Markdown 编辑与草稿，不开放云端保存。此前提出方向后用户决定跨电脑交接，第 08 轮尚未写代码。

1. 从现有云端预览组件及相邻测试入手，增加 Markdown 编辑入口、源码/预览双栏，复用安全 Markdown 渲染。
2. 捕获编辑基准版本，区分云端读取内容、编辑草稿和预览。不能把最新 head 静默当成旧草稿的基准版本。
3. 支持返回预览、明确丢弃草稿和草稿恢复。明确返回预览是否保留草稿，避免隐式丢弃。
4. 先确定持久化范围与退出登录清理规则，再实现存储。隔离登录身份、tenant、doctype 和 docId，不复用公开本地 PSD 样例的存储键，不在草稿记录中保存令牌。
5. 存储失败不能显示“已保存”。本轮不开放云端保存，不显示虚假的保存成功；本地草稿状态必须与云端提交区分。

验收：编辑、安全预览、返回预览与丢弃、刷新恢复、身份隔离、退出清理、存储失败、云端版本变化时保留原草稿及基准版本，全过程无云端内容修改请求。检查桌面和平板布局，手机保持既有范围。

先做最小编辑状态及测试，再接恢复，完成后补第 08 轮交付记录。不要为这一轮先做全仓库重构。

## 后续：可靠云端保存

第 09 轮再接显式提交与服务端持久提交结果。冲突保留草稿；网络中断显示结果待确认并核实原次提交，不能靠再次提交猜结果。

- 创建状态跟踪不是 apply receipt，不能证明内容修改已持久保存。
- `DocSession.applyLocal` 会自动 drain，409 会 rebase 并用同一 opId 重放，不能直接用于显式保存语义。
- recentOps 缓存不是持久幂等结果；Cloudflare 和共享 session 有不同实现路径，见 P0 能力矩阵。
- 当前 `/ir?version=...` 不保证历史读取，不得将当前内容伪装成指定历史版本。
- iframe 暂不作为第 08 轮前置条件，但保持宿主管鉴权、版本和提交，编辑器管内容与草稿的边界。
- PSD 云端编辑、历史版本、批注和版本引用仍待后续实现。

## 新电脑环境

pnpm monorepo，前端使用 React、TypeScript、Vite、Vitest 和 Testing Library。先检查 package.json、锁文件和工具链。不要假定原电脑的端口、进程、cfg 配置或浏览器登录可用。IndexedDB 草稿和 sessionStorage 跟踪不会跨电脑同步。浏览器需重新获取页面，不复用旧会话 pageId。

```sh
pnpm install --frozen-lockfile
pnpm --filter @unidocs/web-gateway dev --host 127.0.0.1 --port 5184
```
